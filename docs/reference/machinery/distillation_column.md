# 蒸馏塔配方与运行

配方类位于 `common/mini_jei/machinery/distillation_column.py`，继承 `MachineRecipe`。
在 `common/machinery_def/distillation_column.py` 的 `recipes` 集合中填写实际配方；树脂配方为每 200 tick 输入 244 mB，产出树油 100 mB 和熔融松香 144 mB。
`common.export.recipes` 导出 `DistillationColumnRecipe`、`DistillationFraction`。

## 配置示例

以下 ID 和数值仅用于说明字段，不是已注册配方。温度单位 K，进料单位为每批整数 mB，热耗单位 RF热/mB。`tick_duration` 表示满速处理一批所需 tick，默认 1。标称输入及各路输出必须为整数 mB；运行时仍按温度和批次时长换算连续流量。

```python
recipes = RecipesCollection(
    DistillationColumn.CONTROLLER,
    DistillationColumnRecipe(
        input_fluid="example:feed",
        input_volume=40,
        tick_duration=4,
        min_temperature=350.0,
        fit_temperature=500.0,
        max_temperature=700.0,
        feed_heat_cost=2.0,
        fractions=[
            DistillationFraction("example:light", 0.25, 350.0, 450.0, 10.0),
            DistillationFraction("example:middle", 0.35, 450.0, 550.0, 12.0),
            DistillationFraction("example:heavy", 0.25, 550.0, 650.0, 15.0),
        ],
        residue_fluid="example:residue",
    ),
)
```

每条配方有 1～3 种轻到重排列的馏分及最后一路残液，共 2～4 路输出。
占比总和必须小于 1；所有输出 ID 互异且不同于原料，残液不能再冒充原料反复提取。
同一原料的温区重叠时按集合声明顺序取第一条，不因其输出受阻而改跑另一条。

## 温度模型

- 在有限温度 `T > min_temperature` 时加工，不因超过旧的 `max_temperature` 而暂停。
- 进料倍率为 `min(1, (T-min)/(fit-min))`；达到适宜温度后保持满速，继续按实际处理量扣热。
- `max_temperature` 暂时保留为旧配方参数与序列化兼容字段（沿用原有参数校验），不再代表停机温度；游戏内 UI 温度提示暂未同步调整。
- 每种馏分的 `x=clamp((T-evap_start)/(evap_full-evap_start),0,1)`，回收率为 `x*x*(3-2*x)`。
- 馏分量为进料量 × 占比 × 回收率。未回收部分全部计入残液。
- 热耗为进料量 × 基础热耗 + 各馏分量 × 汽化热耗。
- 库存不足或供热不足时统一缩小处理量；扣热不能使温度低于配方最低温度。
- `Marshal/Unmarshal` 保存具名参数并重建标称输入输出；配方页显示充分回收时的理论量，不代表当前温度产量。

当前树脂配方在 `T <= 450 K` 时暂停，`450 < T < 500 K` 时线性提速，`T >= 500 K` 时保持满速，包括超过旧上限 600 K 的情况。树油在工作温区内始终充分回收，产出比例不变：每 244 mB 液态生树脂得到 100 mB 树油及 144 mB 熔融松香，不新增过热残液或损失。
原料与输出空间充足时，满速每 tick 处理 1.22 mB，产出树油 0.5 mB、熔融松香 0.72 mB，配方耗热 3.22 RF热；每 200 tick 合计耗热 644 RF热。供热与环境散热另行结算，继续加工不保证温度一定下降。

## 接口与提交规则

按世界坐标 `(-y, x, z)` 排序取最高四个输出口。实际库存始终在接口，控制器输出字段仅用于显示。
按配方顺序一一映射已有接口；缺少接口的尾部馏分/残液直接丢弃，仍完整扣取对应原料与热耗。
配方未使用的额外接口不阻塞加工。使用中的接口满或放不下本次缩放后的产量时整批暂停；正产量对应口装着异种流体也暂停。
所有检查完成后统一提交原料、输出和热量，再发送通知。暂停时不扣取控制器原料及配方热耗。
输入接口到控制器的补料、环境散热和外部供热是独立行为，暂停配方时仍可发生。

## 游戏内验收

使用已注册的流体替换示例 ID，再验证：

1. 在 500K，缩放前每 tick 输入 10mB，依次输出 2.5、1.75、0、5.75mB，耗热 66 RF热。
2. 两个输出口仅保存前两路，尾部丢弃；原料和热耗保持上述完整值。三口时第四路丢弃。
3. 填满任一已用口，或让容量不足/装入异种液体：库存与配方热耗均不提交；清空后恢复。
4. 配方最低温度边界、适宜温度、原料不足和热量不足；等于或低于最低温度暂停，达到适宜温度后保持满速，超过旧最高温度仍加工并扣热。树脂配方检查 450、475、500、600、601、800 K：475 K 为半速，其余高于或等于 500 K 的测试点处理量、产出比例与配方热耗相同。
5. 交换输出口高度、同高度多口、超过四口、接口卸载重载和结构破损；不得串口、重复产物或使用旧实例。
6. 保存重进后检查输入库存、接口库存、温度与显示快照；配方页可查看 2/3/4 路输出及温度提示。

不使用系统 Python 执行或编译模组代码；上述运行用例需在游戏的 Python 2.7.13 环境验收。
