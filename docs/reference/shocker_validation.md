# 电击器验收记录

2026-11-11，在用户授权的测试存档内使用游戏内 Python 2 运行时验证。未在游戏外执行、编译或导入模组 Python。

## 已实现规则

- 方块 `skybluetech:shocker`，无 UI，复用原有 `shocker.geo.json` 和 `shocker_texture.png`。
- 六向放置，每台存电 16000 RF，仅相对后面和上面输入。
- 两台面对面、间隔 1～3 格配对，`GetBlockBasicInfo` 的 `solid=true` 阻断。
- AOI 回调维护进入、离开；上升沿处理区域内生物，任一端导通时处理新进入的生物。恢复配对或加载时若仍导通，也处理已有生物。
- 脉冲和首次建立已导通配对时额外查询一次区域快照，避免 AOI 初始回调异步而漏掉短脉冲；持续入区检测仍使用 `CreateEntityAOI`，没有逐 tick 实体轮询。
- 仅处理当前生命值 `0 < N < 40` 的普通生物，排除玩家、非生物及已禁用 AI 的目标。每台扣除 `ceil(100 * N * 间隔格数 / 2)` RF，双方都够支付才执行。
- 多目标逐个结算。缺电时双方均不扣电，调用一次 0 伤害并显示弱火花；留在区域内补电或改变生命值不会自动重试。
- 正常电击也在昏死和扣电完成后调用一次 0 伤害；正常与弱电两条分支均每个目标调用一次。此补充已做源文本检查，尚未追加游戏内回归。
- 成功后写入永久昏死标记，移除自主行为、寻路、移动控制、跳跃、攻击、投射、传送等组件，四类自主速度及跳跃力归零。引擎 AI 保持开启，保留原有 `physics`、`pushable`、`buoyant`，仍可受传送带、重力和水流等外力推动。
- 加载时按永久标记重新施加昏死；兼容旧版关闭 AI 的标记实体，将引擎 AI 恢复为 true 后施加新机制。相关 JSON 事件添加的自主行为、攻击组件也会再次移除。
- 拦截昏死来源对玩家的伤害；组件重配时短暂保护接触状态效果，防止河豚在移除毒性组件前施毒。不清除昏死生物的投射物，原记录中的相关说法已按 2026-11-14 用户纠正撤销。
- 成功每批次播放一条两电极间 shader 电弧。静态模型没有方块实体外观加载事件，因此放电时筛选同维度、距任一端 128 格内玩家发送 S2C，客户端再检查两端方块存在。

## 配对、供电与显示检查

下表记录此前完成的机器检查；当时关闭 AI 的实现已被上述新机制替换。新版生物行为、外力与最终机器回归结果见下一节。

| 场景 | 结果 |
| --- | --- |
| 六个朝向分别面对面、间隔 1 格 | 六对均配对成功，AOI 边界正确 |
| 六向相对后、上输入面 | 实例 `energy_io_mode` 均符合方向映射；朝上为下/南，朝下为上/北 |
| 10 血牛，间隔 1 格，物理红石上升沿 | 每台 16000 → 15500 RF，生命值仍 10，永久标记为 true |
| 持续红石导通，新牛进入 | 无需新脉冲，再次各扣 500 RF，新目标昏死 |
| 初版保存重进与状态恢复 | 电量、标记保存及重进重施路径通过；当时的关闭 AI 方式已废弃，新版迁移结果见下节 |
| 一侧 0 RF，另一侧 16000 RF | 双方电量不变，目标未昏死，生命值仍 10，弱击调用一次 |
| 缺电后原地补电 | 不重复弱击、不自动扣电或昏死 |
| 0 伤害底层行为 | `Hurt(0, Lightning, ..., False)` 返回 false，但实测 `DamageEvent` 确实收到一次 `damage=0`、无击退、无点燃；不能把返回 false 当作事件未发生 |
| 两个 10 血目标、两端各 500 RF | 一只昏死，另一只未昏死，两端均剩 0 RF，生命值不变 |
| 当前血量 40，已进入区域 | 不昏死、不扣电 |
| 在区域内把血量从 40 改为 39 | 不误判为新进入；新脉冲后才昏死 |
| 39 血，间隔 3 格 | 每台 16000 → 10150 RF，即各扣 5850 RF |
| 插入实心阻挡 | 配对和 AOI 被移除，目标未昏死 |
| 持续导通，拆掉实心阻挡 | 立即重建配对并电击已有目标；10 血、间隔 3 格各扣 1500 RF |
| shader 和模型显示 | 原有模型/贴图正常；真实 shader 载体创建成功，电弧连接两电极尖端 |
| 服务端到客户端强弱效果 | 实际 S2C 已收到强电弧和弱火花事件；强效果有 shader 载体，弱效果无电弧、产生三处粒子；寿命结束后活动效果为 0 |
| 水流破坏 | 流水抵达后机器变为 `water aux=8`，机器池卸载该实例 |

通过 `SetBlockNew` 放置静态水源不会立即启动流动。本次先读取中间格确认仍为空气，再将水源下方方块石头→空气，触发真实邻居更新；流水到达后，原有 `netease:water_destory` 即正确生效，无需添加另一套液体组件。

## 2026-11-11 新版昏死实测

本轮使用独立、完整的 `SKYBLUE_SOLID_CHECK` 测试场地，未改动用户原有机器。

| 场景 | 结果 |
| --- | --- |
| 牛、僵尸、骷髅、兔子、史莱姆、末影人、女巫、烈焰人、苦力怕、蜜蜂、恶魂 | 11 类目标昏死后受禁组件数均为 0；原有物理组件保留，引擎 AI 保持 true |
| 旧版标记迁移 | 已有昏死标记、旧方式 AI=false 的牛重载后变为 AI=true，并按新机制昏死 |
| 真实传送带 | 昏死生物在 1.2 秒内移动 1.15 格 |
| 外部 `SetMotion` | 昏死兔子 x 增加 0.44 格 |
| 重力 | 昏死生物 y 从 144 降至 141 |
| 真实流水 | 昏死生物 x 从 10.5 移至 13.074 |
| 新生成僵尸、骷髅 | 分别移除 16、15 个组件；1.2 秒内位置不变 |
| 生存玩家遭强制攻击目标测试 | 将玩家设为上述昏死僵尸、骷髅的攻击目标，3 秒后玩家生命值仍为 20 |
| 按来源阻止伤害 | 手动发起来源为昏死僵尸的 5 点伤害，玩家生命值不变；未昏死牛的 2 点伤害对照使玩家 20 → 18 |
| 河豚 JSON 事件 | `full_puff` 确实会添加 2 点 `area_attack` 和 10 秒中毒 `mob_effect`；昏死及再次触发事件后 0.2 秒内相关组件已移除 |
| 河豚重配时接触玩家 | 修复前可复现短暂施毒；修复后强制鼓起并与生存玩家重叠，连续 9 次逐帧读取均无状态效果、生命值保持 20；未昏死河豚对照造成中毒且生命值 20 → 18 |
| 正常状态效果 | 重配保护窗口内，源已无接触毒性组件时，普通方式施加中毒仍成功 |
| 新版机器完整脉冲 | 真实红石激活、间隔 1 格、10 血牛，两端各 16000 → 15500 RF；标记 true、AI=true、受禁组件为 0、生命值仍 10 |
| 最终保存重进 | 15 个带标记测试目标均为 AI=true、受禁组件为 0；机器电量仍各 15500 RF，没有重复扣电 |
| 机器目标重进后运输 | 上述牛重进后在真实传送带上 1 秒移动 1 格，生命值及机器电量不变 |

状态效果前置事件不提供施加者 ID。因此保护仅在昏死/JSON 重配的短暂窗口（正常 0.2 秒，引擎操作失败重试时续期）、源仍实际具有同名 `mob_effect`、玩家同维度且位于其碰撞盒加效果范围内生效。若其他来源恰好在此时同处该范围施加同名效果，也会被取消；组件移除后不会拦截。其他模组自定义脚本强制施加的运动或攻击不在已验证范围。
