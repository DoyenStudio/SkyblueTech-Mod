# 物品管道的可选 radium 联动

物品管道通过已有 ToolDelta 组件发现获取 radium，不导入其脚本、不增加 manifest 依赖。物品联动要求主版本 1、版本至少 1.2.0；radium 1.1 的能源和流体联动保持可用。未安装或尚未发现组件时继续旧容器流程，发现组件后刷新现有物品管网的端口。

## 搬运选择

每次源容器与目标容器配对时，使用目标方块被接触的绝对面查询双方 `radium:item` 端口：

- 双方均提供端口：在一个根事务中遍历源端实际槽号及完整物品身份，调用 `move_item`；根提交后扣减全网预算。
- 任一方没有端口：仅当双方均有原生容器槽位时，整次使用旧容器搬运，否则跳过。
- 双方有端口但拒收或满载：接受 0，不回退。
- 查询或事务抛出 `TransactionError`：跳过此次配对，下次调度重新查询，不回退。

旧流程完成待写回内容后才进入下一次事务。事务结束后清除物品网络库存缓存，避免 provider 直接写 NBT 未发出容器变化事件时继续使用旧快照。事务内不广播旧存取事件，不直接写入原生容器；权限由端口负责。

输出端继续轮询，目标按现有优先级排序，两种后端共享本轮总预算。未启用物品联动时维持原有整网处理；启用时按源、目标配对完成写回后再处理下一对。

本次不为 SkyBlueTech 机器注册物品 provider，不迁移库存，不提供虚拟库存与原生容器的跨后端原子提交。纯虚拟库存不能通过 fallback 访问。`PushItemToGenericContainer*` 和 `PostItemIntoNetworks` 保留旧行为及返回值。

旧容器路径仍为原有缓存与引擎写回机制，并不因此获得 radium 的回滚保证。radium 保证内存事务，持久化失败由其重试保存，不重放搬运。

## 游戏验收清单

以下场景尚未进行游戏内验收。仅在游戏 Python 2.7.13 解释器中验证，不在外部运行或编译模组脚本。

| 场景 | 预期 |
| --- | --- |
| 不加载 radium、加载 1.1、加载 1.2 | 均正常启动；前两种物品走旧流程，能源与流体行为不退化 |
| 两端事务库存，包含稀疏槽号 | 按真实槽号搬运，源扣减等于目标增加 |
| 同 ID 不同 aux、附魔、耐久、userData | 完整身份保持，不错误合堆；工具与普通物品遵守各自上限 |
| 拒收、满载、输出禁用 | 搬运 0，即使存在原生槽位也不绕过端口权限 |
| 查询失效、根提交前库存变化 | 此次配对不 fallback；事务放弃不改变双方库存 |
| 一方无端口但双方有原生槽位 | 使用旧流程，分面白名单和存取事件取消仍有效 |
| 纯虚拟库存与无端口箱子 | 安全跳过，无扣取、无凭空生成 |
| 六面连接及机器旋转 | 查询使用被接触面，权限对应正确 |
| 双箱两半、多面共享同一 Cell 的端口 | 不向自己搬运，不重复参与或凭空增减 |
| 一网混用两种后端、多源多目标 | 总搬运不超过预算，源轮询和目标优先级有效，旧缓存不覆盖事务结果 |
| 服务延迟发现，区块卸载重载，替换方块 | 端口被刷新，过期代理不跨轮使用 |
| 保存退出重进 | 双方库存保持；另验 provider 保存失败时不重复扣取 |

静态核验：检查 API 名称、版本门槛、方向换算、提交后预算扣减，并运行 `git diff --check --ignore-submodules`。静态核验不能代替上述游戏验收。
